# MVP 1.5 本地 PDF 知识库验证

日期：2026-11-03（北京时间）。Linux、Python 3.12.14、Node 24.22.1、Chromium。测试后端使用8001，前端代理同步指向8001；没有在真实 Mac 设备运行，没有读取或配置私人 API Key。

## 已执行范围

- 真实自建授权 PDF → 浏览器上传 → pypdf正文提取 → 分页/内容块 → SQLite FTS5 → 查询 → 原页图片预览 → 模拟模型引用卡片 → 原 PDF `#page=3`。模型步骤使用明确标注的测试响应，**不是 Gemini 请求**。
- 真实离线中文 OCR：用本机字体自绘扫描页，Tesseract `chi_sim+eng` 识别出中文，保持待核对/待专业审核；不会因OCR置信度高而自动允许发送。
- 七份自建 PDF 批量导入，重复检测、独立元数据、索引进度、继续处理、人工核对内容在重建时保留。
- 云端片段许可：默认关闭，逐本开启后仍需每轮勾选；最多4条、每条480字符。撤销许可或内容改变导致旧片段ID失效时拒绝发送。API测试检查未把另一页正文、文件、图片或整个索引加入模型请求。
- PDF magic/大小/页数/加密/主动内容检查，跨站与非本机Host拒绝，原页越界拒绝。印刷页码与章节需有核对依据；章节仅有原PDF书签时自动提取。

## Mac 最终验收路径

1. 备份已有本地源码改动，切换本分支；保留原 `.env`、Gemini配置和8001端口。安装依赖；扫描书如需OCR先安装本机免费引擎与语言包。
2. 浏览器先导入一份有权使用的小型测试PDF，核对页数、搜索几个独立短语并对照原页。开启这份文档的片段许可，在每轮对话发送前审阅短片段。
3. 用用户已配置的真实 Gemini 问一个明确覆盖测试PDF的中文问题，并追问。检查引用卡片、PDF页码和原页内容，记录实际真实模型结果。
4. 再批量导入七本真实教材，在界面逐本记录实际/可检索/失败/低质量/待OCR/缺处理记录数量。扫描页需核对后才能发给模型。
5. 每本书抽查开头/中间/末尾及含动作图片的页面；分别核对原PDF页码和印刷页码，记录抽样总数、正确数、缺页与错位。遇到识别问题通过本机页面核对、重试，不编造缺失正文。

在以上真实教材与 Gemini 步骤完成前，状态应为“功能已实现、合成资料流程通过；七本真实教材与真实Gemini全链路待验收”。
